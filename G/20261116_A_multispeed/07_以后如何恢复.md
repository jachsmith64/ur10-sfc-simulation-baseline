# 以后如何恢复

## A 电脑从工作分支恢复

从交付说明取得分支与准确提交号，在独立 clone 中 checkout 该提交。进入 `G/20261116_A_multispeed`，保留仓库内相对位置。V02 的 UR10e 网格模型源自父提交中的原文件，通过 SHA-256 核对后复制，Git 中的 `v02_portable` 同步实际运行源码和全部必要小型输入。原 A 帧和 RTDE 紧凑数组位于 `prepared_A`。

在 Windows 的 PowerShell 中，用实际的 Python 3.12.10 和依赖环境运行。已核依赖为 MuJoCo 3.15.0、Ruckig 0.19.4、NumPy 2.5.3 和 SciPy 1.18.1。依赖已有环境可从命令行绑定。如果安装在指定虚拟环境，省略两个 Runtime 选项。计算入口沿用 V02 离线保护。

```powershell
& '<Python.exe>' -X utf8 .\prepare_v02.py .\local\portable_v02
.\reproduce.ps1 -Python '<Python.exe>' -V02Root .\local\portable_v02 -Out .\runs\new_G_replay
```

如需使用完整 A 原件，追加 `-SourceRoot '<交接根目录>'`，其下需要 `data/original`、`data/batch`、`data/derived`、`data/B_reference`。10 mm/s R01 的混合归档入口还需要 `data/analysis_20260902`，目录成员依照 `prepared_A/X_P10_R01/source.json` 的相对路径放置。新试次通过 `-Trials X_P10_R02 X_P20_R01 ...` 传入。追加 `-WithControls` 请求控制组，入口仍要求旧回归、各片基础验收、两个合格速度和微命令验证。

## B 电脑完整冻结版回归

本地完整母版与依赖在本项 `local/frozen_V02`、`local/runtime_local`、`local/runtime_science`。实际源位置与复制件逐文件 SHA-256 在 `evidence/v02_full_copy_manifest.json`。冻结副本不含大量旧扫描输出，原扫描输出仍在 B 原项目。历史数组与环境身份在 `evidence/regression_receipt.json`、`evidence/v02_actual_identity.json`。

```powershell
.\reproduce.ps1 -Python '<Python.exe>' -V02Root .\local\frozen_V02 -MuJoCoRuntime .\local\runtime_local -ScienceRuntime .\local\runtime_science -HistoricalRuns '<原 strong_sfc_20261110/results/runs>' -Out .\runs\new_v02_regression
```

原母版的入口 `reproduce_strong.ps1` 也完整保存。只收到精简历史 ZIP 时，按其恢复说明用原任务 ZIP 与 V01 精简 ZIP 恢复 source_A/source_B/frozen 和运行历史校验。Git 中的可移植 G 路径用于 CB3，验证旧冻结版还需完整 V02 文件清单与原始历史数组。

## ZIP 独立复算

解压后从 ZIP 根目录运行 `python -X utf8 verify_review.py .`。此步骤仅需 NumPy，检查所有成员 SHA-256、三片原时间采样评分、等效力、命令保持及 N 行为。完整运行轨迹、相机帧和命令事件在 B 的 `runs/`，精简数组和每次运行配置在 ZIP `results/`。A 接收 ZIP 的图解、精简结果和验证说明后，将 Git 工作目录接到自己的 G 子项。当前结果属于模拟及拟合过的 A 试次，实机抑振和独立外推仍未验证。
